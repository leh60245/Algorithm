## 1번 — 가위바위보 그래프

### 문제 (재구성)

- 사람들이 그래프로 주어진다. A → B 간선은 "A가 B를 겨냥한다"는 뜻.
- A가 B를 가위바위보로 이기면 **B가 A와 같은 상태로 바뀐다.**
- A와 B가 서로를 겨냥할 수도 있다.
- 상태 변화는 1초마다 **일괄(동시) 적용**된다.
- 답: t초 후 각 사람의 상태.

**입력**

1. 누가 누구를 겨냥하는지 나타내는 리스트 (크기 n)
2. 각 사람의 상태 리스트 (1, 2, 3)
3. 시간 t

**범위**: 기억나지 않음. t가 큰 값이었는지가 3번 함정의 관건.

### 핵심 아이디어

**① 아웃디그리 1 = 함수형 그래프**
겨냥 리스트 크기가 n이라는 건 각자 정확히 한 명을 겨냥한다는 뜻.
`points[i] = j` 형태. 트리들이 사이클에 매달린 구조가 된다.

**② 여러 명이 나를 겨냥해도 충돌이 없다**
어떤 상태를 이기는 상태는 **딱 하나뿐**이므로, 나를 실제로 이기는 사람들은
전부 같은 상태다. "누구 걸로 바뀌지?"를 고민할 필요가 없다.

```
[실험 A] 0,1,2 가 모두 3번을 겨냥. 3번은 '보'.
  겨냥하는 상태 ['가위', '가위', '가위'] -> 실제로 이기는 사람들: ['가위', '가위', '가위']
  겨냥하는 상태 ['가위', '바위', '가위'] -> 실제로 이기는 사람들: ['가위', '가위']
  겨냥하는 상태 ['바위', '바위', '바위'] -> 실제로 이기는 사람들: []
```

**③ 동시 갱신**
읽기는 이전 상태 배열에서, 쓰기는 복사본에. 제자리에서 고치면 같은 초 안에
전파가 연쇄로 일어나 틀린다.

**④ (진짜 함정) 상태는 수렴하지 않는다**
"시간이 지나면 안정된다"고 가정하면 틀린다. 3-사이클에서 영원히 회전한다.

```
[실험 B] 0->1->2->0 사이클, 초기 [가위, 보, 바위]
  t=0: ['가위', '보',   '바위']
  t=1: ['바위', '가위', '보'  ]
  t=2: ['보',   '바위', '가위']
  t=3 에서 t=0 상태로 되돌아옴 -> 꼬리 0, 주기 3
```

따라서 t가 크면 **전체 상태 튜플을 dict에 넣어 사이클을 탐지**하고
`꼬리 + (t - 꼬리) % 주기` 만큼만 시뮬레이션한다.

## 2번 — 청소기 커버리지와 k

### 문제 (재구성)

- n×n 격자를 청소기 여러 대가 청소한다.
- 각 청소기는 거리 k 이내를 청소할 수 있다. (문제에는 맨해튼 거리라고 명시)
- 격자 **칸 사이**에 벽이 있고, 청소기는 벽을 넘어 청소할 수 없다.
- 청소기 위치는 주어진다.
- 답: 청소기별 청소 범위가 **최소한으로 겹치도록** 하는 k.

**입력**

1. 청소기 위치 리스트 `[[i, j], ...]`
2. 벽 위치 리스트 `[[r1, c1, r2, c2], ...]`

**미해결 의문**: "겹침 최소"를 글자 그대로 읽으면 k=0이 정답이 되어 버린다.
실제 문제에는 "전체를 다 청소하면서" 같은 추가 조건이 있었거나,
"겹치지 않는 최대 k"를 묻는 형태였을 가능성이 높다. 조건 재확인 필요.

### 핵심 아이디어

**① 벽이 있으면 그건 더 이상 맨해튼 거리가 아니다**
문제에 "맨해튼"이라고 써 있어도 벽이 등장하는 순간 BFS 최단거리로 바뀐다.
이걸 놓치면 전부 오답.

```
[실험 E] 벽은 col2 | col3 사이 (0~3행). 청소기 (0,0)
  맨해튼 거리:           실제 BFS 거리:
    0  1  2  3  4          0  1  2 11 12
    1  2  3  4  5          1  2  3 10 11
    2  3  4  5  6          2  3  4  9 10
    3  4  5  6  7          3  4  5  8  9
    4  5  6  7  8          4  5  6  7  8
```

오른쪽 위 칸은 맨해튼으로 3인데 실제로는 11이다.

**② 벽은 칸이 아니라 간선을 막는다**
`(r1,c1,r2,c2)` 는 두 인접 칸 사이의 이동을 막는 것.
`blocked` 집합에 정방향/역방향을 **둘 다** 넣고 BFS 이동 직전에 검사한다.

**③ 겹침은 k에 대해 단조증가 → 이분탐색 가능**
다만 청소기마다 BFS를 한 번씩 돌려 두면 직접 계산된다.
"두 범위가 처음 겹치는 k" = `min over 칸( max(dA, dB) )`.
청소기가 M대면 각 칸에서 가까운 두 대까지의 거리 중 큰 값의 최솟값.

```
[실험 F] 청소기 (0,0), (0,4)
  두 범위가 처음 겹치는 k = 6  ->  겹침 0 을 유지하는 최대 k = 5
  k=5 일 때 겹치는 칸 수 = 0
  k=6 일 때 겹치는 칸 수 = 1
```

## 3번 — 무한 보드와 주사위

### 문제 (재구성)

- 무한히 긴 보드판. 출발 위치는 0.
- 주사위를 굴려 나온 값만큼 앞으로 간다. (주사위 눈은 어떤 값이든 나올 수 있음)
- **위험 구역은 (n+1)의 배수 위치마다** 있다. 밟으면 출발 위치(0)로 돌아간다.
- 원할 때 스스로 출발 위치로 돌아갈 수도 있다.
- 앞으로 나올 주사위 눈을 **미리 다 알고 있다.**
- 답: 최대한 멀리 갔을 때의 위치값.

**입력**

1. n
2. 앞으로 나올 주사위 눈 리스트

### 핵심 아이디어

**① 상태는 `위치 % (n+1)` 하나로 압축된다**
위험 구역이 (n+1)의 배수이므로, 죽느냐 마느냐는 나머지만 보면 된다.
무한한 위치 공간이 (n+1)개의 상태로 줄어든다.

**② 자발적 리셋은 주사위를 소모하지 않는다 — 이게 이득의 근원**
위험 구역을 밟는 것과 자발적 리셋은 결과 위치가 똑같이 0이지만,
밟으면 그 주사위를 버리는 것이고 자발적 리셋은 주사위를 아낀다.

```
[실험 D] n=3(위험구역 4,8,12...), 주사위=[2,2,5]
  리셋 X : 0 -(2)-> 2 -(2)-> 4(위험!)->0 -(5)-> 5      최대 5
  리셋 O : 0 -(2)-> 2 [리셋] 0 -(2)-> 2 -(5)-> 7       최대 7
  코드 확인 -> 리셋X=5, 리셋O=7
```

완전탐색으로 뽑은 반례들:

```
[실험 C] 리셋을 안 쓰면 손해 보는 경우 (완전탐색)
  n=1 (위험구역 2,4,6...), 주사위=[1, 3]     -> 리셋 없이 1, 리셋 쓰면 3
  n=1 (위험구역 2,4,6...), 주사위=[1, 5]     -> 리셋 없이 1, 리셋 쓰면 5
  n=1 (위험구역 2,4,6...), 주사위=[3, 5]     -> 리셋 없이 3, 리셋 쓰면 5
  n=1 (위험구역 2,4,6...), 주사위=[1, 1, 2]  -> 리셋 없이 1, 리셋 쓰면 3
```

**③ DP**
`dp[i][r]` = i번째 주사위까지 처리했고 위치의 나머지가 r일 때의 최대 실제 위치.
전이는 매 턴 두 갈래 — (a) 그대로 굴리기, (b) 0으로 리셋한 뒤 굴리기.
굴린 결과가 (n+1)의 배수면 0으로 떨어진다.
답은 "최대한 멀리"이므로 전 과정의 최댓값을 따로 추적한다.

복잡도: `O(len(dice) × (n+1))`
